IQR Method

IQR Outlier Detection Column: {{ results.iqr.column }}

What is IQR Outlier Detection?
The Interquartile Range (IQR) method identifies outliers by computing the spread of the middle 50% of the data. Values below Q1 − 1.5×IQR or above Q3 + 1.5×IQR are flagged as outliers and clipped to the boundary. Applied here to {{ results.iqr.column }}.

Ordinal Encoding
Assigns a unique integer to each category in a defined order (e.g. low=0, medium=1, high=2). Unlike One-Hot, it preserves the rank relationship between categories. Only valid when categories have a meaningful order.
Not Applied in This Dataset
Ordinal encoding requires columns with a natural rank order (e.g. rating: low < medium < high). The categorical column track_genre contains 114 music genres with no meaningful ordering — applying ordinal encoding here would introduce false numeric relationships (e.g. "acoustic" = 0, "pop" = 50, "classical" = 100 implies classical > pop > acoustic, which is meaningless). One-Hot or Embedding encoding is more appropriate for this column.
Applied to columnsNone — no ordinal columns in this dataset
Where it is usedEducation level, satisfaction scores, size ratings (S/M/L/XL)
AdvantageCompact (1 column), preserves order for tree-based models
LimitationImplies numeric distance between categories that may not exist
When to useOnly when categories have a true, known rank order
Target Encoding
Each category is replaced by the mean value of the target column for that category, computed from the training set only. This captures the relationship between category and outcome directly, and handles high-cardinality columns well. Applied here using targets: explicit and mode.
Applied to columns {% for c in results.categorical_cols %}{{ c }} {% endfor %}
Target variables explicit mode
Where it is usedGradient boosting models (XGBoost, LightGBM, CatBoost)
AdvantageSingle column per feature; handles high cardinality; target-aware
LimitationRisk of target leakage if not computed exclusively on training data
Leakage preventionEncoding fitted on training set only, then applied to test set

Feature Scaling

Scaling Methods

Why scale features?
Numeric features have very different ranges — e.g. duration_ms (50k–500k) vs danceability (0–1). Without scaling, models that use distances or gradients (KNN, SVM, neural networks) will be dominated by high-magnitude features. Both scalers are fitted on the training set only to prevent data leakage.
